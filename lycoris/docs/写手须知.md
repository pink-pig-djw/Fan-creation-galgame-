# 写手须知（《花期》）

你负责《花期》的某一章。动笔前**全部读完**：
1. `docs/设定集.md`——时间线、原作事实、人物、称呼表、变量、结局。
2. `docs/大纲.md`——全部分场。你那一章的大纲是骨架：可以加细节、加小场面、调整节奏，**关键事件、选项、变量、结局条件不能改**。
3. `script/01_ch1.js`——序章和第一章的成稿。**文风、旁白语气、节奏、命令用法以它为准。**你的章节要能接在前一章后面读下去。
4. `js/assets.js`——能用的背景、立绘表情、CG、说话人、结局、档案 id。**只能用这里有的 id。**
5. `js/audio.js` 里的 `TITLES`（BGM 名）、`startAmb` 里的 `target`（环境音名）、`se()` 里的 `case`（音效名）。

## 交付
- 只写你自己的文件。不要改其他任何文件。
- 文件格式：`SCRIPTS.push(String.raw\`` …… `\`);`
- 第一个标签是你的入口（见大纲表）。标签和 `@node` id 都用你的前缀，别和别人撞。
- 每个场景开头放 `@node 节点id|分支图上的短标题`（2～8 个字）。BAD END 也要有自己的 `@node`。
- 章节开头：`@chapter 第X章|标题|日期副标题`（幕间用 `@chapter 幕间|标题|`）。每个场景开头用 `@date 主行|副行` 标日期地点，例：`@date 9月4日（一）　21:30|锦糸町　小巷`。
- 章节结尾 `@jump 下一章入口`。BAD END 结尾 `@ending id` → `@totitle`。
- 写完运行 `node tools/validate.js 你的文件名`（例如 `node tools/validate.js 02_ch2`）。ERRORS 全部修好；WARNINGS 里的「speaks without sprite」要修到 0。别的章节入口标签缺失和缺图（missing image files）不用管——图还在画。
- 再运行 `node tools/validate.js -ai 你的文件名`，它会列出疑似「AI 味」的句子。**一条一条改掉**，目标是 0；「——」每千字不超过 3，「微微/轻轻/淡淡……」每千字不超过 1.5。

## 体量
- 按大纲表的字数写，**宁可写满，不要写短**。字数指显示出来的文字（旁白＋台词）。
- 日常要好笑、要具体；枪战要有节奏、要爽；黑暗的地方要真的疼。三种调子交替，不要一个调子写到底。

## 尺度
- 本作比一般同人放得开：枪战里可以有血、有人死（只有汐见、DA 狙击手、清扫部会杀人；**千束永远不杀人**，泷奈在正线里也不杀人）。泷奈被关押的部分写实：挨打、被按进水里、手被踩碎，写出痛，不要写成虐待展览，镜头跟着她的意识走。
- 可以骂人（「混蛋」「该死」「他妈的」），符合人物就行。风希、瑞希、乌丸骂得最多，泷奈几乎不骂，千束生气时不骂、反而变安静。
- 千束和泷奈的感情可以写得浓：牵手、靠在一起、睡一张床、抱、掉眼泪。**不写任何性的内容。**

## 文风：尽量没有「AI 味」（最重要）

读者会一句一句看。下面这些写法一出现，就会被看出来是机器写的。**一律不要用**：

### 禁止清单
1. **比喻泛滥**。「像……一样」「仿佛」「宛如」「如同」「好似」。一个场景最多一个比喻，而且要具体、要像千束会说的（「像电影里第二个死的那种配角」可以，「像一首无声的挽歌」不行）。
2. **句式模板**。「不是 X，而是 Y」「与其说 X，不如说 Y」「X，却又 Y」「没有 X，没有 Y，只有 Z」「既 X 又 Y」。
3. **三连排比、对仗**。「她想起……，想起……，想起……」。
4. **把情绪直接说出来**。「她感到一阵悲伤」「心里五味杂陈」「心头一紧」「鼻子一酸」「眼眶发热」「一股寒意」「莫名的不安」「复杂的情绪」「心里一暖」。写人做了什么、看到了什么，情绪让读者自己读出来。
5. **套话动作**。「深吸一口气」「空气仿佛凝固」「时间仿佛静止」「沉默在蔓延」「嘴角勾起一抹弧度」「眸子」「眸中闪过」「指节泛白」「喉咙发紧」「瞳孔骤缩」「愣了一下」「顿了顿」——全篇这些加起来不超过三次。
6. **结尾升华**。场景的最后一句不许总结道理、点题、抒情。「也许，这就是……」「原来……」「她终于明白了……」「有些东西……」统统不要。最后一句用一个动作、一句台词、一个物件结束。
7. **角色说出主题**。没有人会说「活着就是要做想做的事」这种格言——千束的信条可以说，但要像她平时挂在嘴边的口头禅那样随口说，不要郑重其事。
8. **副词堆叠**。「微微」「轻轻」「淡淡」「缓缓」「静静」「默默」——一段里最多一个。
9. **抽象名词**。「某种东西」「什么东西碎掉了」「一种说不清的感觉」「温度」（比喻意义的）「重量」（比喻意义的）。
10. **标点**。破折号「——」每千字不超过 3 个；省略号「……」只用在话真的说一半的地方，不要每句台词都带。旁白不要用感叹号抒情（千束吐槽时可以有）。
11. **对话后挂说明**。「她说，声音很轻。」「他低声道。」少用。台词本身要能让人听出语气。
12. **翻译腔**。「这很 X」「做出了一个……的动作」「她的脸上写满了……」「一个……的微笑」。
13. **工整**。不要每段一样长、每句一样长。可以有很短的一句。可以有不完整的句子。可以有跑题的细节。

### 要这样写
- **具体**：时间（21:12）、东西（拿铁拉花歪了、桌游是「狼人杀」的哪个角色、泷奈的笔记本是方格纸）、声音（门上的铃、咖啡机的蒸汽）、钱（一杯咖啡 480 円）。
- **台词短**。像真人说话：会说半句、会答非所问、会重复、会用「嗯」「诶」「那个」。一句台词一般不超过 30 字。
- **千束的旁白**：口语、轻快、爱吐槽、会跑题。她是一流的观察者：看手、看肩膀、看站位、看视线、看枪口，看到了就说出来（「他右手一直在口袋里，口袋的形状是刀柄」）。她**不分析自己的心情**——难过的时候她会去做别的事、说一句不相干的话、或者干脆写「我没说话」。偶尔用电影打比方（一章一两次，要具体）。
- **泷奈的旁白**（幕间）：冷、短、像报告。痛的时候数东西。
- **好笑要干**：互相吐槽、一本正经地说蠢话（泷奈）、瑞希的婚活惨剧、胡桃的毒舌。不要写成段子，不要加「哈哈哈」。
- **枪战靠动作和节奏**：短句、空行（`@wait`）、`@shot`、`@shake`。写清楚谁在哪、子弹往哪飞、千束看见了什么。不要用形容词堆「激烈」。

### 对照
| 不要 | 要 |
|---|---|
| 一股寒意从脊背升起，空气仿佛凝固了。 | 电视里的女主播说：「一名二十岁女性死亡。」<br>画面上是小春住的那栋楼。 |
| 她深吸一口气，眼中闪过一丝复杂的情绪，轻轻地说：「我没事。」 | 「我没事。」<br>我把杯子放回桌上，放歪了，又扶正。 |
| 那不是悲伤，而是一种更深的、无法命名的空洞。 | 我把那个牌子翻过来，又翻回去。背面什么都没写。 |
| 也许，这就是活着的意义吧。 | （直接结束场景，或者写一个动作：）我把围裙系上了。 |
| 泷奈愤怒地瞪着她，声音颤抖地说：「你根本不懂！」 | 泷奈：「这是最有效率的办法。」<br>泷奈：「……你也知道。」 |

## 剧本格式（命令参考）

一行一条。空行忽略。`//` 开头是注释。

### 文本
- `旁白文字` —— 没有名字的行是旁白（千束的第一人称「我」；幕间是泷奈的「我」）。
- `名字：台词` —— 说话。名字必须是 `js/assets.js` 里 `speakers` 的键（千束、泷奈、米卡、瑞希、胡桃、楠木、风希、樱、汐见、小春、灯、乌丸、山岸、沼田），或者是**没有立绘的路人/画外音**（例如「男人」「女主播」「真岛」「老板娘」「广播」「无线电」）。路人说话前后要交代清楚是谁。
- 台词里**不要**加「」引号，引擎会处理。旁白里引用别人的话可以用「」。
- `（心里话）` —— 整行用全角括号括起来的旁白，显示成主角的心声（会带头像）。少用，一场一两句。
- 旁白里不要出现「名字：」这种冒号句式（会被当成说话人）。
- 一行不超过 110 字，一般 20～60 字。

### 画面
- `@bg 背景id [dissolve|cut|black|white] [毫秒] [keep]` —— 换背景。默认会清掉所有立绘和天气；加 `keep` 保留立绘。
- `@show 角色id 表情 [位置] [动作] [flip]` —— 立绘。位置：`l` `cl` `c` `cr` `r`（左到右）。动作：`shake` `tremble` `hop` `pop`。`flip` 左右翻转。表情 id 见 assets.js（带 `cafe_` `casual_` `pj_` `captive_` 前缀的是换装）。
- `@hide 角色id` / `@hide all`
- `@face chisato 表情` —— 只换千束的对话框头像表情（她不在画面上时，说话会显示头像）。换装场景记得同步：在店里 `@face chisato cafe`，在家 `@face chisato pj` 等等。
- `@cg id [毫秒]` / `@cg off [毫秒]` —— 事件 CG。CG 显示时，在场角色说话不需要立绘。
- `@shot [次数] [rifle|silenced]` —— 枪声：音效 + 屏幕闪光 + 震动。默认 1 发手枪。`@shot 3` 连射三发。`@shot 1 rifle` 狙击枪。`@shot 1 silenced` 消音。
- `@heart` —— 千束的心跳（音效 + 画面边缘红色脉动一次）。全篇用不超过 6 次。
- `@fx rain|heavyrain|dust|none` —— 粒子。**rain 只能在户外背景用**（validate 会查）。
- `@tint red|cold|memory|dark|none` —— 画面色调。`memory` 用于回忆。
- `@shake` `@flash [颜色]` `@black [毫秒]` `@white [毫秒]` `@reveal [毫秒]` `@wait 毫秒` `@glitch [毫秒]`
- `@textbox hide|show`
- `@center 文字` —— 黑底居中的一行字（可用 `\n` 换行）。

### 视角
- `@pov takina` —— 切到泷奈视角（幕间开头用）：心声、头像都变成泷奈。`@pov chisato` 切回来（幕间结尾必须切回）。

### 声音
- `@bgm 名字 [淡入秒]` / `@bgm stop [淡出秒]`
- `@amb 名字` / `@amb stop [名字]` —— 环境音。
- `@se 名字`

### 分支
- 选项：
```
@choice
> 选项文字 => 跳转标签 | clue+1 clue_chain=1
> 另一个选项 => 另一个标签
```
  效果写在 `|` 后面，用空格分开：`变量+数` `变量-数` `变量=数`。没有跳转标签就接着往下走。可用变量：`clue` `clue_chain` `clue_plate` `clue_fuki`。
- `@set clue+1` —— 改变量。
- `@if 条件 => 标签` —— 条件成立就跳。例：`@if clue>=2 => c6_true_duel`、`@if clue_plate==1 => c5_plate`。
- `@jump 标签`
- `@node id|短标题` —— 分支图节点。
- `@ending id` —— 结局卡。`@credits cgid` —— 片尾字幕。`@totitle` —— 回标题。
- `@mode phone` —— 电话的显示样式；`@mode normal` 恢复。电话那头的人说话不需要立绘（会显示头像；真岛没有头像，只显示名字）。
- `@line 标题` —— 打开手机聊天窗（短信）。打开时，`名字：内容` 会变成聊天气泡。`@line off` 关闭。

### 立绘规则（玩家很在意）
- **在场的角色说话时，他的立绘必须在画面上**（或者正在显示 CG）。不在场的（电话、短信、无线电）用 `@mode phone`。
- 千束：一个人的时候、独白的时候，不放立绘（对话框会显示她的头像）。**和别人对话的时候，千束的立绘上场**：`@show chisato 表情 l`，对方站在 `r`（需要的话加 `flip` 让人物朝向对方）。三个人时千束在 `l`，其他人 `c` `r`。
- 同一个场景里不要换衣服。千束的服装：任务 / 外出调查 = 制服（无前缀）；店里 = `cafe`；休息日 = `casual`；家里晚上 = `pj`。泷奈同理，被关押时 = `captive`，第六章获救以后 = 制服或 `captive`（她还穿着那身），终章 = `casual_hurt`。
- 换场景（`@bg`）之后，立绘要重新 `@show`。
- 一个画面最多 4 个立绘，一般 1～3 个。
- 胡桃：DA 的人在场时她不能出现在画面上（她躲着）。
