# 写手须知（《四十九日》）

你负责《四十九日》的某一章。动笔前**全部读完**：
1. `docs/设定集.md`——时间线、原作事实、人物、称呼表、美佳色相、结局。
2. `docs/大纲.md`——全部分场。你那一章的大纲是骨架：可以加细节、加小场面、调整节奏，**关键事件、选项、数值、结局条件不能改**。
3. `script/01_ch1.js`——序章和第一章的成稿。**文风、旁白语气、节奏、命令用法以它为准。**你的章节要能接在前一章后面读下去。
4. `js/assets.js`——能用的背景、立绘表情、CG、说话人、结局、档案 id。**只能用这里有的 id。**
5. `js/audio.js` 里的 `TITLES`（BGM 名）、`startAmb` 里的 `target`（环境音名）、`se()` 里的 `case`（音效名）。

## 交付
- 只写你自己的文件。不要改其他任何文件。
- 文件格式：`SCRIPTS.push(String.raw\`` …… `\`);`
- 第一个标签是你的入口（见大纲表）。标签和 `@node` id 都用你的前缀，别和别人撞。
- 每个场景开头放 `@node 节点id|分支图上的短标题`（2～8 个字）。BAD END 也要有自己的 `@node`。
- 章节结尾 `@jump 下一章入口`。BAD END 结尾 `@ending id` → `@totitle`。
- 写完运行 `node tools/validate.js 你的文件名`（例如 `node tools/validate.js 02_ch2`）。ERRORS 全部修好；WARNINGS 里的「speaks without sprite」要修到 0。别的章节入口标签缺失（例如 `missing label c3`）和缺图（missing image files）不用管。
- 再运行 `node tools/validate.js -ai 你的文件名`，它会列出疑似「AI 味」的句子（比喻词、套话、升华……）。**一条一条改掉**，目标是 0；「——」每千字不超过 3，「微微/轻轻/淡淡……」每千字不超过 1.5。

## 体量
- 按大纲表的字数写，**宁可写满，不要写短**。字数指显示出来的文字（旁白＋台词）。
- 每章至少一处让人心里发冷的地方，至少一处能让人笑一下的地方（一系的日常、志恩的玩笑、Dime、雏河的结巴）。恐怖和日常要交替，不要从头冷到尾。

## 文风：尽量没有「AI 味」（最重要）

读者会一句一句看。下面这些写法一出现，就会被看出来是机器写的。**一律不要用**：

### 禁止清单
1. **比喻泛滥**。「像……一样」「仿佛」「宛如」「如同」「好似」。一个场景最多一个比喻，而且要具体（「像没关好的水龙头」可以，「像一首无声的挽歌」不行）。
2. **句式模板**。「不是 X，而是 Y」「与其说 X，不如说 Y」「X，却又 Y」「没有 X，没有 Y，只有 Z」「既 X 又 Y」。
3. **三连排比、对仗**。「她想起……，想起……，想起……」。
4. **把情绪直接说出来**。「她感到一阵悲伤」「心里五味杂陈」「心头一紧」「鼻子一酸」「眼眶发热」「一股寒意从脊背升起」「莫名的不安」「复杂的情绪」。写人做了什么、看到了什么，情绪让读者自己读出来。
5. **套话动作**。「深吸一口气」「空气仿佛凝固」「时间仿佛静止」「沉默在蔓延」「嘴角勾起一抹弧度」「眸子」「眸中闪过」「指节泛白」「喉咙发紧」「瞳孔骤缩」「愣了一下」「顿了顿」——全篇这些加起来不超过三次。
6. **结尾升华**。场景的最后一句不许总结道理、点题、抒情。「也许，这就是……」「原来……」「她终于明白了……」「有些东西……」统统不要。最后一句用一个动作、一句台词、一个物件结束。
7. **角色说出主题**。没有人会说「悲伤不是软弱」「哀悼需要时间」这种话。只有白鹭可以讲他的理论，而且他讲得也要像一个具体的人在说话（带着他自己的经历和细节），不是格言。
8. **副词堆叠**。「微微」「轻轻」「淡淡」「缓缓」「静静」「默默」——一段里最多一个。
9. **抽象名词**。「某种东西」「什么东西碎掉了」「一种说不清的感觉」「温度」（比喻意义的）「重量」（比喻意义的）。
10. **标点**。破折号「——」每千字不超过 3 个；省略号「……」只用在话真的说一半的地方，不要每句台词都带。不要用感叹号表达旁白的情绪。
11. **对话后挂说明**。「她说，声音很轻。」「他低声道。」少用。台词本身要能让人听出语气。
12. **翻译腔**。「这很 X」「做出了一个……的动作」「她的脸上写满了……」「一个……的微笑」。
13. **工整**。不要每段一样长、每句一样长。可以有很短的一句。可以有不完整的句子。可以有跑题的细节。

### 要这样写
- **具体**：时间（21:52）、温度、菜名（土豆炖肉、炖萝卜）、东西的样子（拖鞋摆得很整齐，鞋尖朝外）、声音（冰箱的压缩机停了）。
- **台词短**。像真人说话：会说半句、会答非所问、会重复、会用「嗯」「啊」「那个」。一句台词一般不超过 30 字。
- **旁白是朱的视角**：她是刑警，观察细、判断快、对自己的情绪很迟钝。她注意到的是：谁的手在抖，杯子里还有多少茶，门是朝哪边开的。她不分析自己的心情，最多陈述事实（「我没有哭。」「我把那条留言又放了一遍。」）。
- **恐怖靠细节和节奏**，不靠形容词。少写「可怕」「诡异」「毛骨悚然」——写那个东西本身：门禁扫描器说出一个死人的名字，桌上多了一杯茶，影像说错了一件只有奶奶知道的事。短句、空行（`@wait`）、音效、`@glitch`。
- **幽默是干的**：一系的人互相吐槽，志恩的不正经，宜野座一本正经地抢狗嘴里的手套。不要写成段子。

### 对照

|---|---|
| 一股寒意从脊背升起，空气仿佛凝固了。 | 门禁扫描器响了一声。「欢迎回家，宫野拓真先生。」<br>拓真坐在我对面，筷子还拿在手里。 |
| 她深吸一口气，眼中闪过一丝复杂的情绪，轻轻地说：「我没事。」 | 「我没事。」<br>我把杯子放回桌上，放歪了，又扶正。 |

| 也许，这就是哀悼的意义吧。 | （直接结束场景，或者写一个动作：）我把烟按灭了。 |
| 美佳愤怒地瞪着她，声音颤抖地说：「你根本不懂！」 | 美佳：「你懂什么。」<br>美佳：「你什么都不懂。你连——」<br>她没说下去。 |

## 剧本格式（命令参考）

一行一条。空行忽略。`//` 开头是注释。

### 文本
- `旁白文字` —— 没有名字的行是旁白（朱的内心独白，第一人称"我"）。序章是由纪的第一人称。
- `名字：台词` —— 说话。名字必须是 `js/assets.js` 里 `speakers` 的键（朱、美佳、宜野座、六合塚、雏河、志恩、禾生、七濑、白鹭、奶奶、鞠、Candy、加贺美、主宰者，以及群众角色名）。
- 台词里**不要**加「」引号，引擎会处理。旁白里引用别人的话可以用「」。
- `（心里话）` —— 整行用全角括号括起来的旁白，显示成朱的心声（会带朱的头像）。少用，一场一两句。
- 旁白里不要出现「名字：」这种冒号句式（会被当成说话人）。
- 一行不超过 110 字，一般 20～60 字。

### 画面
- `@bg 背景id [dissolve|cut|black|white|holo] [毫秒] [keep]` —— 换背景。默认会清掉所有立绘和天气；加 `keep` 保留立绘。`holo` 是全息开关的扫描线切换（例如 `@bg scene_off holo`）。
- `@show 角色id 表情 [位置] [动作] [flip]` —— 立绘。位置：`l` `cl` `c` `cr` `r`（左到右）。动作：`shake` `tremble` `hop` `pop`。`flip` 左右翻转（让朱在左边时面朝右）。
- `@hide 角色id` / `@hide all`
- `@face akane 表情` —— 只换朱的对话框头像表情（她没在画面上时，说话会显示头像）。
- `@cg id [毫秒]` / `@cg off [毫秒]` —— 事件 CG。CG 显示时，在场角色说话不需要立绘。
- `@scare cgid` —— 惊吓演出：瞬间切到 CG ＋ 尖锐音效 ＋ 震动。全篇最多 4 次，别滥用。
- `@glitch [毫秒]` —— 画面故障（全息/电子干扰），自带音效，不用再加 `@se glitch`。
- 台词或旁白里用 `〔……〕` 括起来的字会显示成被干扰的闪烁文字（全息影像说话出错的地方用，少用）。
- `@fx rain|heavyrain|snow|dust|static|none` —— 粒子。**rain/snow 只能在户外背景用**（validate 会查）。`static` 是噪点。
- `@tint red|cold|memory|dark|none` —— 画面色调。`memory` 用于回忆。
- `@shake` `@flash [颜色]` `@black [毫秒]` `@white [毫秒]` `@reveal [毫秒]` `@wait 毫秒`
- `@textbox hide|show`
- `@center 文字` —— 黑底居中的一行字（可用 `\n` 换行）。

### PSYCHO-PASS 演出
- `@scan 名字|数值|判定` —— 主宰者瞄准界面（原作那种投影在视野里的青色界面）。数值是数字（会逐位跳动）或 `—`。判定例：`对象外　扳机锁定`、`执行模式：非致命瘫痪`、`执行模式：致命处决`。界面会一直留在屏幕上，直到 `@scan off`（换背景时也会自动消失）。
- 主宰者的语音是说话人「主宰者」，**用原作的台词句式**（短句，用顿号般的停顿）：
  - 启动：`主宰者：携带型心理诊断镇压执行系统·主宰者，已启动。使用者认证：常守朱监视官。公安局刑事课所属。确认使用许可。是适格使用者。`（全篇只完整说一次，之后可以省略）
  - 瘫痪：`主宰者：犯罪系数，超过 100。是执行对象。执行模式：非致命瘫痪。请冷静瞄准，制服对象。`
  - 处决：`主宰者：犯罪系数，超过 300。执行模式：致命处决。请慎重瞄准，排除对象。`
  - 不是对象：`主宰者：犯罪系数，低于 50。不是执行对象。扳机锁定。`（数值为 0 时说「犯罪系数，0。」）
  - 全息影像（没有心理测量值）：`主宰者：无法取得对象的心理测量值。不是执行对象。扳机锁定。`
- `@hue mika` / `@hue akane` —— 弹出色相检查面板（几秒后自动消失）。美佳用变量 `mika` 的当前值。
- `@tip id` —— 解锁一条搜查档案（id 见设定集第 2 节）。第一次出现这个概念的地方放一次。
- `@countdown N|日期` —— 全屏倒数卡「距离四十九日 还有 N 天」。`N=0` 显示「四十九日」。每章开头用一次。
- `@date 主行|副行` —— 左上角的日期卡。例：`@date 12月14日（五）　09:10|公安局　刑事课一系`

### 声音
- `@bgm 名字 [淡入秒]` / `@bgm stop [淡出秒]`
- `@amb 名字` / `@amb stop [名字]` —— 环境音（雨、空调、城市……）。
- `@se 名字`

### 分支
- 选项：
```
@choice
> 选项文字 => 跳转标签 | mika+6 keep=1
> 另一个选项 => 另一个标签 | mika-4
```
  效果写在 `|` 后面，用空格分开：`变量+数` `变量-数` `变量=数`。没有跳转标签就接着往下走。
- `@set mika+15` —— 改变量。
- `@if 条件 => 标签` —— 条件成立就跳。例：`@if mika>=100 => bad_turbid`、`@if keep==0 => c3_dinner_new`。
- `@jump 标签`
- `@node id|短标题` —— 分支图节点。
- `@ending id` —— 结局卡。`@credits cgid` —— 片尾字幕。`@totitle` —— 回标题。
- `@mode phone` —— 电话、语音留言的显示样式；`@mode normal` 恢复。电话那头的人说话不需要立绘（会显示头像）。

### 立绘规则（玩家很在意）
- **在场的角色说话时，他的立绘必须在画面上**（或者正在显示 CG）。不在场的（电话、留言、无线电）用 `@mode phone`。
- 朱：一个人的时候、独白的时候，不放立绘（对话框会显示她的头像）。**和别人对话、对峙的时候，朱的立绘上场**：`@show akane 表情 l flip`，对方站在 `r`。三个人时朱在 `l`，其他人 `c` `r`。
- 同一个场景里不要换衣服（朱的 `home` 只在她家里用）。
- 换场景（`@bg`）之后，立绘要重新 `@show`。
- 一个画面最多 4 个立绘，一般 1～3 个。
- 全息影像（`aoi` `shirasagi_holo` `candy` `kagami` 等）也是立绘，同样要在场。

### 美佳色相的数值
- 按大纲写，**数值一个都不要改**。选项效果写在选项行里；剧情固定变化用 `@set`。
